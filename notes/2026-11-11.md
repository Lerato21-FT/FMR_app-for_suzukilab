# 2026-11-11: four-quadrant page (task 9)

## Request and decisions

The user asked to replace the long column of settings with four quadrants,
modelled on the LabVIEW front panel. They answered the plan's questions:

1. Save folder: a relative folder name under `data/measurements/`. Nothing
   is written outside the repository (AGENTS.md).
2. Angle: stays a single value, used only in the file name, until the
   stepper motor is ported.
3. Instrument tabs: named as in the VI (H field setup, A83640B, SR830,
   Stepper Motor).

## What changed

- `RunSettings.save_folder` is validated at the API boundary: up to four
  `/`-separated names, starting with a letter or digit and not ending in a
  dot. Windows device names (CON, NUL, COM1 and the like) are refused.
  `SweepStore` also refuses any path that resolves outside its directory.
  Sweep file names in the plan and run summaries now include the folder.
- `GET /api/settings/defaults` returns `data_dir` (relative to the repo when
  inside it), so the page shows where the folder will be created.
- Page: `index.html`, `styles.css` and `app.js` rewritten for the 2×2 grid,
  with tab keyboard navigation (arrows, Home, End) and the preview as a
  table. The row of the sweep being measured is highlighted.
- `make run-sim`: starts the app with simulated instruments even when
  `.env` selects hardware. (`.env` currently says `hardware`, so `make run`
  would open VISA sessions.)
- Task 8 work that was still uncommitted was committed first, separately.

## Tests

`tests/2026-11-11/test_save_folder.py` failed first against a naive version
(an unvalidated field, and a path helper that ignored the folder): 19
failures. It passed after the real implementation. `test_page_layout.py`
statically checks the quadrants, the tab names, that every `RunSettings`
leaf has an input, and that every element the script looks up exists.
`make verify` is green: 77 tests and the smoke check.

## Not verified

  widths.
- No real hardware was used.

## Follow-up: stale page files after the update

When the user opened the page, the quadrants were stacked and the tabs did
nothing. The browser had fetched the new `index.html` but kept running its
cached `styles.css` and `app.js` from before. Starlette sends no
`Cache-Control`, so browsers cache files heuristically from
`Last-Modified`. Ctrl+Shift+R fixed it, which confirmed the cause. The page
files are now served with `Cache-Control: no-cache`
(`api.RevalidatedStaticFiles`), so the browser revalidates them on every
load. Unchanged files still return a cheap 304. The test
`test_page_files_are_revalidated_on_every_load` failed four times before
the fix and passes after it.
